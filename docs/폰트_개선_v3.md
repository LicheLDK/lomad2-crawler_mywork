# UI 개선 제안 v3 — Modern & Sophisticated

관련 문서: [`폰트_개선.md`](./폰트_개선.md) · [`폰트_개선_v2.md`](./폰트_개선_v2.md) · [`UI_개선/작업내용.md`](./UI_개선/작업내용.md)

## 0. 진단 — 현재 상태

v1/v2 문서는 "Pretendard + Inter, Linear/Vercel 블루 톤"을 제안했지만, 실제 코드(`web/src/index.css`,
`web/tailwind.config.js`, `components/ui/*`)는 다른 방향으로 구현되어 있습니다.

- **폰트**: `Fraunces`(디스플레이 세리프) + `IBM Plex Sans`(본문) — 이미 개성 있는 웜 에디토리얼 톤
- **컬러**: `ink`(슬레이트) / `sand`(웜 오프화이트) / `teal`(포인트) / `brick`(경고성 톤)
- **컴포넌트**: `rounded-xl`~`2xl`, `shadow-soft` 단일 톤, `backdrop-blur` 카드, 아코디언 사이드바

즉 "제네릭 SaaS 블루 대시보드"가 아니라 이미 자기 색깔이 있는 상태입니다. v3의 목표는 **이 방향을
갈아엎는 게 아니라, 깊이감·완성도·디테일을 더해 "만든 지 얼마 안 된 느낌"에서 "다듬어진 프로덕트
느낌"으로 끌어올리는 것**입니다. 현재 부족한 지점:

| 영역 | 현재 | 문제 |
|---|---|---|
| Elevation | `shadow-soft` 한 가지만 전역 사용 | 카드/드로어/모달/호버 상태가 시각적으로 구분 안 됨 |
| 다크모드 | `color-scheme: light` 하드코딩, 다크 토큰 없음 | 야간 운영 모니터링 대시보드인데 다크모드 부재 |
| 데이터 시각화 | 숫자 타일(`text-2xl` 텍스트)만 존재 | 트렌드·추이를 한눈에 못 봄, "분석 대시보드"라기엔 밋밋 |
| 로딩/빈 상태 | `"통계를 불러오는 중…"` 텍스트 | 스켈레톤 없음 → 로딩 시 레이아웃이 텅 빈 느낌 |
| 배지 | `text-[10px]` pill, 카운트만 | 상태 표현이 약함(색만으로 구분) |
| 모션 | `fadeUp`/`pulseSoft` 2종 | 페이지 전환, 리스트 stagger, 카드 hover 등 디테일 모션 부재 |
| 타이포 스케일 | `font-display text-xl/2xl` 등 페이지마다 즉흥 사용 | 문서화된 스케일이 없어 화면마다 크기가 미세하게 다름 |

## 1. 컨셉

## 2. 컬러 시스템 — 확장

기존 `ink/sand/teal/brick` 팔레트는 유지. 아래를 보강한다.

- **Accent 보강**: `teal-700`(#0f766e) 단독 사용이라 포인트가 약함. 그라디언트 포인트를 카드 상단
  hairline이나 "오늘의 활동" 강조 요소에 한정적으로 추가 — `linear-gradient(90deg, teal-500, brick-500)`.
  전면 사용 금지(에디토리얼 톤 훼손), 강조가 필요한 1~2곳(활성 상태 인디케이터, 차트 라인)에만.
- **Semantic 상태색 재정의**: 현재 `rose`(danger)만 팔레트 외부에서 차용 중. `success`/`warning`은
  tailwind 기본값을 그대로 씀 → `ink`/`sand` 톤과 채도가 안 맞음. 웜톤에 맞춘 채도 낮은 semantic 컬러 추가:
  - success: `#3f7d5c` (sand 배경과 조화되는 sage green)
  - warning: `brick-500`(`#d97706`) 재사용 — 이미 있음, 그대로 승격
  - danger: `#b3413a` (기존 rose-600보다 웜톤에 맞는 톤)
- **다크모드 토큰** (`dark:` 접두 or `data-theme="dark"`):
  - `ink-950`(#0c1222)을 배경으로, sand 톤을 `#1b1712` 근처 웜 다크로 별도 정의(순수 슬레이트 다크는
    현재 웜 정체성과 부딪힘) — `sand-dark-900: #17140f`, `sand-dark-800: #211c15`
  - teal 포인트는 다크에서 `teal-400`으로 밝기 보정(대비 확보)

## 3. 타이포그래피 — Pretendard 단일 체계로 정정

### 3.1 왜 Fraunces를 내리는가

`Fraunces`는 **라틴 전용 세리프로 한글 글리프가 없다.** 현재 화면 텍스트의 대부분(케이스 제목, 사이드바
라벨, 카드 헤더, 검색 키워드 — "당근마켓", "검토 필요" 등)은 한글이라, `font-display: 'Fraunces', Georgia,
serif`를 걸어도 실제로는 Fraunces가 적용되지 않고 조용히 `Georgia`/시스템 세리프로 폴백된다. 즉 "에디토리얼
세리프"라는 디자인 의도가 숫자와 극히 일부 영문 라벨에만 반쪽으로 적용되고, 나머지 대부분의 텍스트는
의도하지 않은 기본 세리프로 렌더링되던 상태였다. 이게 지금까지 "뭔가 다듬어지지 않은" 인상의 실질적 원인 중
하나였다.

### 3.2 대안 — Pretendard Variable 단일 체계

본문·헤딩·KPI 숫자까지 전부 **Pretendard Variable** 하나로 통일한다. 한글 커버리지가 완전하고
100~900 굵기를 모두 가진 가변 폰트라 헤딩에 700을 안 써도 위계를 만들 수 있다. "그냥 흔한 SaaS 산세리프"로
보이지 않게 만드는 디테일은 굵기와 자간이다.

- **굵기**: 헤딩/타이틀은 700(볼드)이 아니라 **600~650**만 사용 — 두꺼운 볼드는 국내 SaaS 템플릿에서
  가장 흔하게 쓰이는 조합이라 오히려 평범해 보인다.
- **자간(tracking)**: 큰 사이즈(페이지 타이틀 27px+, KPI 숫자 30px+)에 `letter-spacing: -0.02 ~ -0.03em`을
  적용 — Linear/Vercel 헤딩이 고급스러워 보이는 핵심 디테일은 서체가 아니라 이 타이트한 자간이다.
- **데이터 폰트**: Job ID, 타임스탬프, 계약번호처럼 숫자·영문 코드 성격의 텍스트에는 `JetBrains Mono`를
  보조 폰트로 사용해 대비를 준다 (기존 Code Font 방침 유지).
- **폴백 스택**: `'Pretendard Variable', Pretendard, -apple-system, 'Apple SD Gothic Neo', 'Malgun Gothic',
  system-ui, sans-serif` — OS 시스템 한글 서체 자체가 Pretendard와 근본적으로 닮은 계열이라 폰트 로드
  실패 시에도 이질감이 적다.

| 토큰 | 크기/굵기/자간 | 용도 |
|---|---|---|
| `display-lg` | Pretendard 32/650, -0.025em | 페이지 타이틀 (Overview, Search 등 h2) |
| `display-md` | Pretendard 22/650, -0.02em | 섹션 타이틀 (카드 헤더, Summary) |
| `display-sm` | Pretendard 18/600, -0.015em | 서브 섹션, 강조 숫자(작은 타일) |
| `metric` | Pretendard 30/650, -0.025em, tabular-nums | KPI 숫자 전용 (OverviewTile, DashboardSummary 값) |
| `body` | Pretendard 14/400 | 본문 |
| `caption` | Pretendard 12/400 | 보조 텍스트, hint |
| `eyebrow` | Pretendard 11/500, tracking-[0.16em], uppercase | 현재 각 페이지 상단 라벨 — 이미 쓰는 패턴, 토큰화만 |
| `data` | JetBrains Mono 12~13/400, tabular-nums | Job ID, 타임스탬프, 계약번호 |

숫자(KPI, 카운트, 테이블 수치)는 전부 `tabular-nums` 강제 — 현재 일부만 적용됨.

> 참고: 에디토리얼 느낌을 완전히 포기하기 아쉽다면, 한글이 섞이지 않는 영역(브랜드 워드마크 "Lomad" 등)에만
> 세리프를 남기는 하이브리드도 가능하지만, 관리 포인트가 늘어나는 트레이드오프가 있어 이 문서에서는
> 채택하지 않는다.

## 4. Elevation — 3단 스케일

`shadow-soft` 하나로 카드/드로어/버튼 hover를 전부 처리 중. 아래 3단으로 분리:

```
shadow-1 (resting card)   0 1px 0 rgba(15,23,42,.04), 0 8px 20px -14px rgba(15,23,42,.14)
shadow-2 (hover / popover) 0 2px 0 rgba(15,23,42,.05), 0 16px 32px -16px rgba(15,23,42,.22)
shadow-3 (drawer / modal)  0 24px 64px -20px rgba(15,23,42,.32)
```

카드 hover 시 `shadow-1 → shadow-2` + `translateY(-1px)` (현재 `Scale 1.01` 대신 translate가 에디토리얼
톤에 더 어울림). Drawer(`ResultDrawer`)는 `shadow-3`로 승격해 배경과의 분리감을 강화.

## 5. 컴포넌트별 개선안

### 5.1 카드 (`components/ui/card.tsx`)
- 현재 `shadow-none` 고정 → 위 elevation 토큰 적용, hover 인터랙션 있는 카드만 `shadow-1 hover:shadow-2`
- 카드 상단에 1px hairline 강조선(선택적) — `before:` 그라디언트로 "활성/중요" 카드 구분

### 5.2 배지 (`components/ui/badge.tsx`)
- 현재 카운트 pill만 존재. **상태 도트 배지** 변형 추가 (`● Open` 형태) — Investigation 상태,
  Worker/Queue 상태 등에서 색+텍스트 조합이 색맹 접근성과 정보 밀도 둘 다 개선
- `variant="dot"` 추가: `<span className="h-1.5 w-1.5 rounded-full bg-current" /> + label`

### 5.3 KPI 타일 (`OverviewPage.tsx`, `DashboardSummary.tsx`)
- 현재 숫자만 표시. **미니 스파크라인**(최근 7일 추이, 12px 높이) 또는 **전일 대비 증감 화살표**
  추가 — `recharts` sparkline 또는 순수 SVG(의존성 최소화 시)
- 숫자 변경 시 count-up 애니메이션(150~250ms) — 폴링 갱신 시 "살아있는" 느낌

### 5.4 로딩/빈 상태
- `"통계를 불러오는 중…"` 텍스트 → 카드 형태 그대로인 스켈레톤(`animate-pulseSoft` 기존 keyframe 재사용)
- 빈 검색 이력/케이스 리스트에 일러스트 대신 아이콘 + 짧은 설명 + CTA 버튼 패턴 통일

### 5.5 사이드바 (`AppSidebar.tsx`)
- 활성 항목이 `bg-ink-900` 풀필로만 표시됨 → 좌측 2px 세로 인디케이터 바(teal) 추가해 Linear식
  "얇고 정확한" 느낌 보강, 풀필은 유지하되 톤 다운
- Collapsed 모드 아이콘에 hover 시 툴팁(현재 `title` 속성만 존재 — 네이티브 툴팁 대신 커스텀 툴팁으로
  디자인 통일)

### 5.6 테이블 (검색 결과, 계약 목록 등)
- Sticky 헤더 + zebra 대신 **hover row 강조 + 클릭 가능 row에 우측 chevron** (v2 문서의 Table 규칙과
  동일 방향, 실제 컴포넌트에 미적용 상태로 보임 — 적용 확인 필요)

### 5.7 검색 툴바 (`SearchToolbar.tsx`)
- Input height 44px, focus 시 teal ring — 기존 유지
- 검색 중 상태를 버튼 텍스트 변경보다 **인라인 progress bar**(툴바 하단 1px)로 표시해 "무거운 작업"
  느낌을 가볍게

## 6. 데이터 시각화 (Analytics, Overview)

현재 숫자 타일 나열이 전부. 대시보드가 "분석" 메뉴를 표방하는 만큼 최소한의 시각화 도입 권장:

- 검색 통계: 일별 검색량 바 차트(최근 14일)
- 사이트별 통계: 도넛 또는 가로 바 차트(중고나라/번개장터/당근 비중)
- AI 분석 통계: 호출 수 추이 라인 차트
- 라이브러리: `recharts`(가볍고 Tailwind와 궁합 좋음) 신규 추가 필요 — 번들 크기 고려 시 Analytics
  페이지에서 lazy import

## 7. 모션 토큰화

현재 `fadeUp`/`fadeOutSoft`/`pulseSoft` 3종만 정의. 아래 규칙으로 확장:

| 대상 | 지속시간 | easing |
|---|---|---|
| Hover (버튼/카드) | 150ms | ease-out |
| 아코디언/드로어 | 250~300ms | cubic-bezier(0.32,0.72,0,1) (현재 사이드바 아코디언과 동일 계열) |
| 페이지 전환 | 200ms | fadeUp 재사용, stagger 없이 컨테이너 1회만 |
| 리스트 아이템 등장 | 40ms stagger, 최대 6개까지만 | fadeUp |
| KPI 숫자 갱신 | 200ms | count-up + 배경 pulseSoft 1회 |

## 8. 다크모드

- `index.css`의 `color-scheme: light` 제거, `prefers-color-scheme` 대응 + 수동 토글(우측 상단 아이콘)
- 사이드바/카드 backdrop-blur는 다크에서 배경 대비가 무너지기 쉬우므로, 다크 모드에서는 blur 대신
  solid `sand-dark-800` 배경 권장
- 야간 운영 모니터링 용도(Worker/Queue 상태 확인)를 고려하면 다크모드 우선순위는 상당히 높음

## 9. 우선순위 실행 계획

| 단계 | 내용 | 난이도 | 효과 |
|---|---|---|---|
| 1 | Elevation 3단 토큰화 + 카드/드로어 적용 | 낮음 | 즉각적인 "고급감" 상승 |
| 2 | 타이포 스케일 토큰화(Tailwind theme) 후 전 페이지 치환 | 낮음 | 일관성 |
| 3 | 스켈레톤 로딩 상태 도입 | 낮음 | 체감 완성도 상승 |
| 4 | 상태 도트 배지 variant 추가 | 낮음 | 정보 가독성 |
| 5 | KPI 타일 스파크라인/증감 표시 | 중간 | Analytics-like 느낌 |
| 6 | 사이드바 액티브 인디케이터 바 | 낮음 | 디테일 |
| 7 | Analytics 페이지 차트 도입(recharts) | 중간~높음 | "분석 대시보드" 완성 |
| 8 | 다크모드 | 높음 | 운영 편의성 + 프로덕트 완성도 |

1~4는 기존 컴포넌트 구조를 거의 바꾸지 않고 토큰/variant만 추가하는 수준이라 리스크가 낮습니다.
5, 7은 신규 차트 라이브러리 의존성이 필요하고, 8(다크모드)은 전 컴포넌트 대상 톤 재검증이 필요해
별도 작업으로 분리하는 것을 권장합니다.
