# 백오피스(lomad2-admin) ↔ Search Crawler 연동 가이드

> **범위:** 이 문서는 **가이드만** 정리합니다.  
> 백오피스 소스(`lomad2-admin_mywork`)는 **수정하지 않습니다.**  
> 구현 위치는 Search Crawler(`lomad2-crawler`)와, 추후 백오피스에서 버튼을 붙일 때의 참고용입니다.

## 1. 목표 플로우

```
Laravel 쇼핑몰 BackOffice — 주문 상세 (/getOrderInfo?order_id=…)
        │
        ├── [중고 검색]          ← 즉시 Search Job 생성 (결과 대기 ❌)
        │         │
        │         ▼
        │   POST /api/search-jobs { orderNo }
        │         │
        │         ▼
        │   Toast: 「검색이 시작되었습니다.」
        │         │
        │         ▼ (백그라운드)
        │   Search Server: 크롤링 → AI 분석 → Investigation
        │         │
        │         ▼
        │   Callback → BackOffice Badge + Search Dashboard 반영
        │
        └── [조사 이력 보기]     ← 기존 Investigation 조회
                  │
                  ▼
            해당 orderNo 의 Investigation 목록
            (Search API 또는 BackOffice 저장분)
```

### Architecture Diagram

```
┌─────────────────────────────────────────────────────────────┐
│  Laravel BackOffice (Master)                                │
│  · 주문 / 계약 / 고객 / 상품 DB                              │
│  · 「중고 검색」 → POST /api/search-jobs { orderNo } + Toast  │
│  · 「조사 이력 보기」 → Investigation 조회                     │
│  · GET  /api/internal/orders/:orderId                       │
│  · POST /api/internal/search-jobs/callback  (Badge)         │
└───────────────┬─────────────────────────────▲───────────────┘
                │ orderNo only                │ callback
                ▼                             │
┌─────────────────────────────────────────────────────────────┐
│  Search Server (독립 배포)                                   │
│  RentalClient → RentalService (주문 조회 · 비영속)            │
│       ↓                                                     │
│  SearchJobService (async Job · Progress · Callback)         │
│       ↓              ↓                 ↓                    │
│  search_jobs    search_history   investigation_cases        │
│  (orderNo)      (crawl)          (searchJobId+orderNo)      │
│  /rental — Job Status realtime (WS job:progress)            │
└─────────────────────────────────────────────────────────────┘
```

> 상세(Folder Tree · API Flow · Sequence · Component Tree):  
> `docs/rental_architecture_final.md`

### 원칙

1. Search Server는 **쇼핑몰 주문 DB를 직접 조회하지 않는다.**
2. 모든 주문정보는 **Rental API Client Layer** 로만 조회한다.  
   (`POST /api/search-jobs` 는 `orderNo` 만 받는다.)
3. BackOffice 연동 진입점은 **`POST /api/search-jobs`** (즉시 jobId).  
   내부적으로 기존 `SearchService` / 크롤 큐를 재사용한다.
4. 대시보드 UI는 Rental/Laravel API를 **직접 호출하지 않는다.** (Server의 Client Layer만)
5. Investigation은 **Job(`searchJobId`)과 연결**한다.
6. UI는 Job Status를 **실시간**(WS `job:progress`) 표시한다.

## 2. 백오피스 쪽 진입점 (참고 — 코드 변경 없음)

주문 상세는 admin의 기존 라우트를 사용합니다.

| 항목 | 값 |
|------|-----|
| 라우트 | `GET` / `POST` `/getOrderInfo` |
| 컨트롤러 | `DailySalesController@getOrderInfo` |
| 라우트 이름 | `dailySales.order` |
| 핵심 파라미터 | `order_id` |

### 2.1 주문 상세 UI — 버튼 2개 (권장)

단일 「중고 검색」 대신 **역할을 분리**하는 것을 권장합니다.

```
주문 상세
┌────────────────────────────────────────┐
│  … 주문/계약/상품 정보 …                 │
│                                        │
│  [중고 검색]          [조사 이력 보기]   │
└────────────────────────────────────────┘
```

| 버튼 | 동작 | 대기 |
|------|------|------|
| **중고 검색** | `POST /api/search-jobs` 로 Job 생성 → Toast | **결과 완료를 기다리지 않음** |
| **조사 이력 보기** | 해당 `orderNo` 의 기존 Investigation 조회 | 목록/상세만 표시 |

### 2.2 「중고 검색」 클릭 시 UX (비동기)

검색을 누르면 **결과를 화면에 붙잡고 기다리지 않습니다.**

```
1. POST /api/search-jobs { "orderNo": "…" }
2. 즉시 jobId 수신
3. Toast: 「검색이 시작되었습니다.」
4. 백그라운드: 크롤링 + AI 분석 + Investigation 자동 생성
5. 완료 시
   · BackOffice: Callback → 「검색 완료」 Badge / 알림
   · Search Dashboard (/rental): Job Status · Investigation 반영
```

| 단계 | BackOffice | Search Server |
|------|------------|---------------|
| 클릭 | Toast만 표시, 주문 상세 유지 | Job `pending` → `running` |
| 진행 중 | (선택) Badge「검색 중」 | Progress API / WS |
| 완료 | Callback 수신 → Badge「검색 완료」 | Investigation + Dashboard 갱신 |

> 운영자가 다시 주문 상세에 들어와도 **[조사 이력 보기]** 로 결과를 확인할 수 있습니다.

### 2.3 Search Job 요청 필드

| 백오피스 필드 | Search Job body | 설명 |
|---------------|-----------------|------|
| `order_id` | `orderNo` | 주문번호 (**필수 · 이것만 전달**) |
| — | `sites?` / `useCache?` | 선택 실행 옵션 |

상품명·계약·고객 등은 body에 넣지 않습니다.  
Search Server가 `RENTAL_API` 로 주문을 조회합니다.

> admin의 `/getOrderInfo` 는 **세션 기반 HTML 화면**입니다.  
> Search Server가 이 URL을 그대로 호출하는 방식은 **권장하지 않습니다.**

## 3. 권장 연동 방식 (BackOffice → Search Job)

백오피스 「중고 검색」 구현 시(별도 작업) 권장 패턴:

1. 주문 상세에 **[중고 검색]** / **[조사 이력 보기]** 두 버튼 배치
2. **[중고 검색]** → `POST /api/search-jobs` (`orderNo` only)
3. 응답 `jobId` 저장 + Toast **「검색이 시작되었습니다.」** (완료 폴링으로 UI 블로킹 ❌)
4. (선택) 백그라운드에서만 `GET …/progress` 폴링 → 「검색 중」 Badge
5. Search Server Callback 수신 → 「검색 완료」 Badge + Investigation 건수
6. **[조사 이력 보기]** → 기존 Investigation 목록 (orderNo 기준)

> Progress 조회가 필요할 때만 (선택):  
> `GET /api/search-jobs/{jobId}/progress` 또는 Socket.IO `job:progress`  
> (`/crawl` namespace, `subscribe { jobId }`) — **UI를 블로킹하지 말 것**

### 3.1 설정 (백오피스 `.env` 예시 — 가이드)

```env
CRAWLER_API_BASE=http://127.0.0.1:3100/api
CRAWLER_API_KEY=change-me-api-key
```

`config/services.php` 예시:

```php
'crawler' => [
    'base' => env('CRAWLER_API_BASE', 'http://127.0.0.1:3100/api'),
    'key'  => env('CRAWLER_API_KEY', 'change-me-api-key'),
],
```

### 3.2 Search Job 요청

```http
POST {CRAWLER_API_BASE}/search-jobs
x-api-key: {CRAWLER_API_KEY}
Content-Type: application/json
```

```json
{
  "orderNo": "30001234",
  "useCache": true
}
```

> **주문 마스터(상품명·계약·고객 …)는 보내지 않습니다.**  
> Search Server 가 `RENTAL_API_BASE_URL` 로 BackOffice 주문을 조회한 뒤  
> `SearchKeywordGeneratorService` 가 검색어를 생성합니다.

**즉시 응답 예시**

```json
{
  "jobId": "a1b2c3d4-…",
  "orderNo": "30001234",
  "status": "pending",
  "requestedAt": "2026-07-25T12:00:00.000Z",
  "keywords": [
    "시몬스 뷰티레스트",
    "Beautyrest",
    "뷰티레스트 킹",
    "시몬스 침대"
  ],
  "progress": 0
}
```

| Job status | 의미 |
|------------|------|
| `pending` | 방금 생성됨 |
| `queued` | 검색 대기 |
| `running` | 검색/크롤 진행 중 |
| `completed` | 완료 |
| `failed` | 실패 |

### 3.2.1 Progress API (진행률)

```http
GET {CRAWLER_API_BASE}/search-jobs/{jobId}/progress
x-api-key: {CRAWLER_API_KEY}
```

```json
{
  "jobId": "a1b2c3d4-…",
  "status": "running",
  "currentSite": "bungae",
  "progress": 45,
  "resultCount": 12,
  "searchHistoryId": "…",
  "at": "2026-07-25T12:00:05.000Z"
}
```

| 필드 | 설명 |
|------|------|
| `status` | Job 상태 |
| `currentSite` | 현재 크롤 중인 사이트 코드 |
| `progress` | 0~100 (Progress Bar) |
| `resultCount` | 수집된 결과 수 |

**UI:** HTTP Polling(1~2초) 또는 WebSocket

```
Socket.IO namespace: /crawl
emit subscribe { "jobId": "…" }
on job:progress  → Progress Bar 갱신
```

### 3.2.2 검색 완료 Callback (BackOffice Badge)

Search Server가 검색·Investigation 자동 생성을 마치면 **BackOffice Callback API**를 호출합니다.  
(admin 소스는 이 저장소에서 수정하지 않음 — 수신 API·Badge는 admin에서 구현)

```http
POST {RENTAL_API_BASE_URL}{RENTAL_SEARCH_CALLBACK_PATH}
Content-Type: application/json
x-api-key: {RENTAL_API_KEY}
```

기본 path: `/api/internal/search-jobs/callback`

```json
{
  "jobId": "a1b2c3d4-…",
  "investigationCount": 3,
  "completedAt": "2026-07-25T12:05:00.000Z",
  "orderNo": "30001234",
  "status": "completed"
}
```

| 필드 | 설명 |
|------|------|
| `jobId` | Search Job ID |
| `investigationCount` | 해당 Job에 연결된 Investigation 건수 |
| `completedAt` | 검색 완료 시각 (ISO) |

**BackOffice 권장 처리 (가이드)**

1. Callback 수신 → `jobId` / `orderNo` 로 주문·Job 상태 저장 (`search_completed`)
2. 주문 상세·목록에 **「중고 검색 완료」 Badge** 표시
3. Badge 클릭 시 Investigation 목록 또는 Crawler Dashboard로 이동 (선택)

Search Server `.env`:

```env
RENTAL_API_BASE_URL=https://admin.example.com
RENTAL_API_KEY=…
RENTAL_SEARCH_CALLBACK_PATH=/api/internal/search-jobs/callback
RENTAL_SEARCH_CALLBACK_ENABLED=true
```

`RENTAL_API_BASE_URL` 이 비어 있으면 Callback은 건너뜁니다 (로컬 개발 안전).

### 3.3 PHP 호출 스케치 (구현 시 참고 — admin 미적용)

```php
use Illuminate\Support\Facades\Http;

$base = rtrim(config('services.crawler.base'), '/');
$key  = config('services.crawler.key');

$job = Http::withHeaders(['x-api-key' => $key])
    ->post("{$base}/search-jobs", [
        'orderNo' => (string) $order->order_id,
        'useCache' => true,
    ])
    ->throw()
    ->json();

$jobId = $job['jobId'];

// 폴링
$status = $job['status'];
$terminal = ['completed', 'failed'];
$attempts = 0;
$detail = $job;

while (!in_array($status, $terminal, true) && $attempts < 30) {
    usleep(2_000_000);
    $detail = Http::withHeaders(['x-api-key' => $key])
        ->get("{$base}/search-jobs/{$jobId}")
        ->throw()
        ->json();
    $status = $detail['status'];
    $attempts++;
}

$searchHistoryId = $detail['searchHistoryId'] ?? null;
```

## 4. Search Server — Rental API Client (이미 추가)

주문 정보를 **외부 JSON API**로만 받을 때를 대비한 Client Layer입니다.  
**새 Search 공개 API는 추가하지 않았습니다.**

### 4.1 Folder 구조

```
lomad2-crawler/src/
 ├── api/
 │     ├── index.ts
 │     ├── rental.module.ts
 │     ├── rental.client.ts      # HTTP만 담당
 │     ├── rental.types.ts       # Order/Product/SearchInput 타입
 │     └── rental.service.ts     # 정규화 + Search 입력 변환
 ├── config/
 │     └── rental.config.ts
 └── app.module.ts               # RentalModule 등록
```

### 4.2 API 구조 (아웃바운드 — Laravel JSON API)

| 메서드 | Client | 기본 path (env로 변경) | 용도 |
|--------|--------|------------------------|------|
| `getOrder(orderId)` | `RentalClient` | `GET {RENTAL_API_BASE_URL}/api/internal/orders/:orderId` | 주문 상세 |
| `getProduct(productId)` | `RentalClient` | `GET {RENTAL_API_BASE_URL}/api/internal/products/:productId` | 상품 상세 |
| `resolveSearchInput(orderId)` | `RentalService` | (위 getOrder 후 변환) | `keyword` / `externalProductId` / `referenceImageUrl` |

Search Server `.env` (예시):

```env
RENTAL_API_BASE_URL=
RENTAL_API_KEY=
RENTAL_API_TIMEOUT_MS=10000
RENTAL_ORDER_PATH=/api/internal/orders/:orderId
RENTAL_PRODUCT_PATH=/api/internal/products/:productId
```

> `RENTAL_API_BASE_URL` 이 비어 있으면 Client는 호출하지 않으며 Job 생성이 실패합니다.  
> BackOffice JSON 주문 API(`GET /api/internal/orders/:orderId`)가 Master 전제입니다.

### 4.3 호출 흐름 (두 가지)

**A. 권장 — 백오피스가 Search Job 생성 (비동기 · Toast)**

```
admin 주문 상세
  → [중고 검색] → POST /api/search-jobs { orderNo }
  → Toast 「검색이 시작되었습니다.」
  → (백그라운드) 크롤 + AI + Investigation
  → Callback → Badge 「검색 완료」
  → [조사 이력 보기] → Investigation 목록
```

Search Server는 주문 HTML(`/getOrderInfo`)을 호출하지 않고,  
`RentalClient` 로 JSON 주문 API만 조회합니다.

**B. Search Server 내부 — 주문 조회 (Job 생성 시)**

```
POST /search-jobs { orderNo }
  → RentalService.resolveSearchInput(orderNo)
  → RentalClient.getOrder
  → KeywordGenerator → async runSearch
```
