# 백오피스 ↔ 크롤러 연동 작업 계획

> 상태: **계획만** (미적용)  
> 작성일: 2026-07-30  
> 대상: `lomad2-admin_mywork` (백오피스) · `lomad2-crawler` (검색/조사 서버)

---

## 1. 업무 프로세스 (기준)

```text
1. 유저 쇼핑몰에서 주문
2. 백오피스에서 주문 확인
3. 백오피스 주문건 모니터링
4. 주문 상품 유저에게 배송
5. 수일 후 재판매 여부 검사 → 중고 탐색 요청 (현재 서버)
6. 크롤러 서버 검색 후 결과 전송
7. 백오피스에서 결과 수신 · 분석
```

| 단계 | 주체 | 크롤러 관여 |
| --- | --- | --- |
| 1~4 | 쇼핑몰 / 백오피스 / 배송 | 없음 |
| 5 | 백오피스 → `POST /api/search-jobs` | Job 생성 |
| 6 | 크롤러 | 검색 · AI · Investigation · callback |
| 7 | 백오피스 | 결과 분석의 **업무 주체** |

## 2. 현황 분석

### 2.1 백오피스 (`lomad2-admin_mywork`)

| 항목 | 경로 / 내용 |
| --- | --- |
| 주문 상세 Controller | `app/Http/Controllers/DailySalesController.php` → `detail()` |
| 주문 상세 View | `resources/views/dailySales/detail.blade.php` |
| 라우트 | `GET|POST /dailySalesDetail` (`dailySales.detail`) |
| 주문 식별자 | `order_id` |
| 검색에 유용한 필드 | `product_code`, `product_detail_code`, `product_id`, `product_name`, `brand_name`, `color`, `easyrental_contract_num`, `username`, `ordersimglist` 등 |
| `routes/api.php` | Internal 주문/콜백 API **미구현** (outbound 일부만) |

`detail.blade.php`는 주문·계약·배송·결제 운영 화면이다. **크롤러에 복제하지 않는다.**

### 2.2 크롤러 (`lomad2-crawler`) — 이미 기대하는 계약

| 방향 | 경로 (기본값) | 설정 |
| --- | --- | --- |
| 주문 조회 | `GET /api/internal/orders/:orderId` | `RENTAL_ORDER_PATH` |
| 상품 조회 | `GET /api/internal/products/:productId` | `RENTAL_PRODUCT_PATH` |
| 검색 완료 콜백 | `POST /api/internal/search-jobs/callback` | `RENTAL_SEARCH_CALLBACK_PATH` |
| Job 생성 (백오피스 → 크롤러) | `POST /api/search-jobs` `{ orderNo }` | 크롤러 API |
| Base URL / Key | — | `RENTAL_API_BASE_URL`, `RENTAL_API_KEY` |

구현 참고:

- `src/api/rental.client.ts`
- `src/api/rental.types.ts`
- `src/config/rental.config.ts`
- `src/modules/search-job/search-job.service.ts` (`create` → Rental API로 주문 조회)

### 2.3 갭

- 백오피스에 **Internal 주문 API / 콜백 API 없음**
- 주문 상세에 **중고 탐색 요청 UI / 스케줄 없음**
- 크롤러 「주문 연동」은 Job 추적 UI로 이미 가능하나, **백오피스에서 Job이 들어와야** 데이터가 쌓임

## 3. 권장 아키텍처

```text
[백오피스 주문 상세]
  ① 중고 탐색 요청 버튼 / 또는 N일 후 스케줄
       ↓ POST /api/search-jobs { orderNo }
[크롤러]
  ② GET 주문조회 ← 백오피스 Internal API
  ③ 검색 · AI · Investigation
  ④ POST callback → 백오피스
[백오피스]
  ⑤ 결과 저장 · 주문 상세에 “탐색 결과” 표시
[크롤러 UI · 주문 연동]
  ⑥ Job 진행 / 콜백 / 연결 조사 추적 (운영 보조)
```

### 역할 분리

| 시스템 | 책임 |
| --- | --- |
| **백오피스** | 언제 검사할지, 주문 원본, 결과 업무 분석(7단계) |
| **크롤러** | 중고 검색 실행, Case, 콜백 |
| **주문 연동 메뉴** | “요청된 Job이 잘 돌았는지” 운영 추적 |

### 화면 경계

| | 백오피스 `detail` | 크롤러 `주문 연동` |
| --- | --- | --- |
| 목적 | 주문·계약·배송 업무 | 탐색 Job 운영 추적 |
| 데이터 | orders DB 원본 | Search Job + 주문 API 스냅샷 |
| 액션 | 상태변경, 메모, **탐색 요청** | 진행 확인, callback 재전송 |
| 결과 분석 | **주 화면** | Case 사전 조사 보조 |

한 줄:  
**백오피스 = 왜/언제 검사할지 + 결과 업무 처리**  
**크롤러 주문 연동 = 검사가 기술적으로 잘 돌았는지**

## 4. Phase별 작업 계획

### Phase 1 — 백오피스 Internal API (필수)

크롤러 `RentalClient`가 이미 호출하는 계약을 백오피스에 구현한다.

#### 1-1. 주문 조회 API

- **Method/Path**: `GET /api/internal/orders/{orderId}`
- **인증**: `x-api-key` 또는 Bearer (`RENTAL_API_KEY`와 동일)
- **데이터 소스**: `DailySalesController@detail` / `getOrdersDetail`와 동일 계열 조회
- **응답 필드 (최소, PII 최소화)**

| 필드 | 출처 예 | 용도 |
| --- | --- | --- |
| `order_id` | `$w->order_id` | Job 키 |
| `product_code` / `product_detail_code` / `product_id` | orders | 외부상품·키워드 |
| `product_name` | orders | 키워드 |
| `brand_name` | orders | 키워드 |
| `color` / size 등 옵션 | orders | 키워드 |
| `easyrental_contract_num` | orders | 계약번호 표시 |
| `username` | orders | 필요 시 마스킹 |
| `thumbnail_img_url` / image | `ordersimglist` 등 | 이미지 유사도 |

**넣지 말 것**: 카드번호, 주소 전문, safekey, 생년월일, 연락처 등 민감정보.

크롤러 `RentalOrderRaw` (`src/api/rental.types.ts`) 필드명과 맞출 것 (snake/camel 혼용 허용됨).

#### 1-2. 검색 완료 콜백 API

- **Method/Path**: `POST /api/internal/search-jobs/callback`
- **Body (크롤러 전송)**: `jobId`, `orderNo`, `status`, `resultCount`, `investigationCount`, `completedAt`, `keywordSummaries` …
- **처리**: 주문별 탐색 결과 테이블에 upsert (예: `order_search_jobs`)
- **실패 시**: 4xx/5xx → 크롤러가 callbackError 기록, 운영자가 「주문 연동」에서 재전송

#### 1-3. (선택) 상품 조회 API

- `GET /api/internal/products/{productId}` — 주문 API만으로 충분하면 Phase 1에서 생략 가능

#### 1-4. 환경 설정

백오피스:

- Internal API Key
- 크롤러 Base URL (`CRAWLER_API_BASE_URL` 등)
- 크롤러 API Key

크롤러 (기존):

- `RENTAL_API_BASE_URL` = 백오피스 API origin
- `RENTAL_API_KEY`
- `RENTAL_ORDER_PATH`, `RENTAL_SEARCH_CALLBACK_PATH`

### Phase 2 — 백오피스에서 탐색 트리거

`detail.blade.php`에 **「중고 탐색 요청」** 버튼 (또는 설치완료 N일 후 배치).

**권장 조건 예**

- 주문 상태 = 설치완료 (`OrderStatusCode::INSTALLATION_COMPLETED = 5`) 이후
- 배송/설치일 + N일 경과 (업무 정책으로 확정)
- 동일 주문에 진행 중 Job이 없을 것

**동작**

1. 백오피스 → 크롤러 `POST /api/search-jobs` `{ "orderNo": "<order_id>" }`
2. 응답 `jobId`를 주문에 연결 저장
3. 주문 상세에 배지: `탐색 대기 / 진행중 / 완료 / 실패`

**스케줄 (후속)**

- “설치완료 + N일” 대상 일괄 요청 Cron/Job

---

### Phase 3 — 백오피스에서 결과 소비

- 콜백으로 받은 요약 표시 (매물 수, Investigation 수, 완료 시각)
- 크롤러 Investigation / 검색 결과 **딥링크** (운영자용)
- **업무 분석의 주 화면은 계속 백오피스 주문 상세**

---

### Phase 4 — 크롤러 「주문 연동」정리

신규 계약 관리 UI를 만들지 않는다. 기존 Job 추적 화면 유지·문구 정리.

- 메뉴: **주문 연동** (이미 반영)
- 탭: 주문 작업 / 자동 검색 / 연결 조사
- 역할: 읽기 전용 + callback 재전송만

## 5. 연동 후 「주문 연동」화면 모습

백오피스에서 탐색을 요청한 주문만 Job으로 쌓인다.

### 왼쪽 — 최근 주문 작업

```text
ORDER-25073001   running 45%
소니 A7M4 · Inv 0 · 방금

ORDER-25072988   completed 100%
캐논 R6 · Inv 2 · 어제
· callback 성공

ORDER-25072810   completed 100%
··· · callback 실패   ← 재전송 가능
```

비어 있으면:  
「백오피스에서 주문 검색을 요청하면 여기에 나타납니다.」

### 오른쪽 — 주문 작업 탭

```text
Job Status     running 45% · 12건 · 번개장터
주문 요약      ← 백오피스 Internal API 재조회 (읽기 전용)
Callback       미전송 / 성공 / 실패 + [재전송]
바로가기       자동 검색 · 연결 조사
```

### 자동 검색 탭

키워드별 건수 → 검색 이력으로 이동

### 연결 조사 탭

해당 Job Case 목록 → Case Drawer  
조사·판정은 **조사** 메뉴에서
