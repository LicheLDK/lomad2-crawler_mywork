# 상품 매칭 (텍스트 · 이미지)

렌탈 주문 상품과 중고거래 검색 결과가 **같은 상품인지** 판단하는 Matching / Investigation 흐름 정리입니다.

관련 문서:

| 문서 | 내용 |
|------|------|
| [환경변수.md](./환경변수.md) | `AI_*` / `AI_LOCAL_*` / `INVESTIGATION_*` 설정 |
| [사용법.md](./사용법.md) | 실행·대시보드 |
| `feature/image-compare` | UI「이미지 비교」Drawer용 `COMPARE_*` 엔진 (Matching과 **별개**) |

---

## 1. 목표

- **같은 이미지**를 찾는 것이 아니라 **같은 상품(모델·색·옵션)** 인지 조사한다.
- 텍스트(제목·브랜드·가격 등)와 이미지(로컬 게이트 → 필요 시 Vision)를 합쳐 AI Score를 낸다.
- 점수가 충분히 높으면 Investigation(연결 조사)을 자동 생성한다.

## 2. 현재 적용된 파이프라인

### 2.1 전체 흐름 (Search Job 기준)

```
주문/상품 스냅샷
  → 키워드 생성 (AI 우선, 실패 시 규칙)
  → 사이트별 크롤 (중고나라 · 번개장터 · 당근)
  → 휴리스틱 titleSimilarity / imageSimilarity (정렬·보조)
  → Job 완료
  → 상위 N건 텍스트 Matching (LLM)
  → [옵션] OCR
  → [조건] 로컬 이미지 게이트 → (통과 시) ChatGPT Vision
  → AI Rules → Investigation 자동 생성
  → BackOffice Callback
```

핵심 코드:

- `src/modules/search-job/search-job.service.ts` — Job 완료 후 Matching + autoCreate
- `src/ai/ai.service.ts` — `matchListing` / `matchSearchResults`
- `src/ai/local-image/` — Color · pHash · SSIM · LooksSame · OpenCV 게이트
- `src/ai/matching-vision.util.ts` — Vision 진입·점수 보정
- `src/ai/rules/` · `src/modules/investigation/` — 자동 생성 규칙

### 2.2 텍스트 Matching (LLM)

Matching 프롬프트가 항목별 점수(0~100)를 내고, 가중 평균으로 종합합니다.

| 항목 | 가중치 | 의미 |
|------|--------|------|
| productName | **0.20** | 상품명 |
| brand | 0.15 | 브랜드 |
| model | 0.15 | 모델 |
| image | 0.15 | 이미지 (Vision/Local 반영 전·후) |
| price | 0.10 | 가격 |
| option | 0.08 | 옵션 |
| color | 0.07 | 색상 |
| description | 0.05 | 설명 |
| ocr | 0.05 | OCR |

- 상위 **15건**만 Matching (`MATCH_BATCH_LIMIT`, 상한 50)
- 정렬: `max(titleSimilarity, imageSimilarity)` 내림차순
- 동시성 2
- `AI_OCR_BEFORE_MATCH` 기본 **false** (켜면 Matching 전 OCR을 프롬프트에 포함)

### 2.3 이미지 Matching (비용 절감 게이트 + Vision)

텍스트 Matching이 어느 정도 높을 때만 이미지 경로에 들어갑니다.

**Vision 후보 사전 조건** (`shouldRunVisionCompare`):

- 양쪽 이미지 URL 존재
- `matchingScore ≥ 50` **또는** brand / productName / model ≥ 60

**로컬 게이트** (`AI_LOCAL_IMAGE_GATE`, 비용 0):

```
전처리 (≤512px)
  → Color      < 35  → Vision 차단 + Local 점수로 보정
  → pHash      < 30  → Vision 차단
  → pHash     ≥ 90  → Vision 스킵(고점, 비용 절감)
  → SSIM      ≥ 92  → Vision 스킵(고점)
  → LooksSame ≥ 70  OR  SSIM ≥ 75  OR  OpenCV ≥ 60
      → 통과 시만 ChatGPT Vision
```

| 엔진 | 역할 |
|------|------|
| Color | 색이 확연히 다른 상품 조기 차단 |
| pHash | 거의 같은 사진 / 완전 다른 사진 조기 판단 |
| SSIM | LooksSame보다 구조 변화에 관대 — 픽셀 엔진 보완 |
| LooksSame | 픽셀 유사도 |
| OpenCV ORB | 특징점 매칭 (각도·부분 촬영 보완) |
| Vision | 유료 — 동일 상품 여부 최종 보정 |

**점수 보정** (`applyVisionToMatching` / `applyLocalToMatching`):

| 이미지 유사도 | 효과 |
|---------------|------|
| &lt; 40 | 텍스트 고점 **강제 하향** (오탐 Investigation 억제) |
| &lt; 60 | 텍스트 고점을 이미지 근처로 제한 |
| ≥ 60 | image 점수 주입 + 가중 평균 블렌드 |

### 2.4 Investigation 자동 생성

| 규칙 | 조건 | 동작 |
|------|------|------|
| `auto_exclude_low_score` | AI Score **&lt; 50** | 생성 제외 |
| `auto_create_high_score` | AI Score **≥ 90** (기본) | Investigation 생성 |
| `price_diff_warning` | 가격 차이 ≥ 70% | Warning만 |

설정: `INVESTIGATION_AI_SCORE_THRESHOLD=90`, `INVESTIGATION_AUTO_CREATE=true`  
→ 예: 최종 59%면 **연결 조사 없음**이 정상입니다.

### 2.5 크롤 단계 휴리스틱 (Matching 전)

| 값 | 계산 |
|----|------|
| `titleSimilarity` | 키워드↔제목 bigram 유사도 |
| `imageSimilarity` | 렌탈 썸네일 aHash 있을 때만 Hamming (없으면 **0**이 흔함) |

이 값은 **상위 N 선정·폴백 점수**에 쓰이고, Search Job Matching이 돌면 LLM/Vision 결과로 덮어씁니다(메모리 상 results).

## 3. 현재 한계 (보완이 필요한 지점)

| # | 한계 | 영향 |
|---|------|------|
| 1 | Matching **상위 15건만** | 그 아래 진짜 동일 상품이 있으면 놓칠 수 있음 |
| 2 | Matching 점수 **DB 미영속** | Job 상세·재분석·콜백에서 재현이 어려움 |
| 3 | OCR 기본 off + listing `ocrText` 미전달 | ocr 가중치(0.05)가 사실상 죽은 항목 |
| 4 | 렌탈 **가격/설명**이 Matching 스냅샷에 약함 | price·priceDiff Rule이 약해짐 |
| 5 | 크롤 `imageSimilarity` 자주 0 | 상위 N 선정에 제목만 의존 |
| 6 | 게이트 **통과 후 Vision만** 반영 | Local(SSIM 등) 점수가 Vision 경로에선 Matching에 안 섞임 |
| 7 | Vision/Local 실패 시 텍스트 점수만으로 진행 | 이미지 없는 “가짜 고점” 가능 |
| 8 | Investigation 임계값 90이 높음 | 동일 상품이어도 연결 조사가 안 생기는 경우 많음 |
| 9 | UI Compare 엔진(`COMPARE_*`)과 Matching 게이트 분리 | 조사 UX와 자동 Matching 결과가 어긋날 수 있음 |

## 4. 보완 추천 (우선순위)

### P0 — 바로 효과 큰 것

1. **Matching 결과 영속화**  
   - `matchingScore` / `aiScore` / 항목 scores / Local·Vision reason을 DB(또는 history result)에 저장  
   - Rental「연결 조사」·검색 카드·재실행에 동일 근거 표시

2. **렌탈 컨텍스트 보강**  
   - Matching 입력에 `price`, `color`, `option`, `description`, 계약/상품코드 전달  
   - `priceDiffPercent` Rule·price 항목 실효성 확보

3. **Investigation 임계값 운영 분리**  
   - “자동 생성”과 “주의 관찰(워치리스트)” 2단  
   - 예: ≥90 자동 Open / 70~89는 `Needs Review` 목록만 (생성은 수동 또는 반자동)

4. **상위 N 확대 또는 2패스**  
   - 1차: 상위 15 LLM  
   - 2차: 로컬 이미지 게이트만으로 남은 후보 중 상위 K개 추가 Matching  
   - 비용은 Local로 막고, 놓치는 동일 상품 줄임

### P1 — 텍스트 Matching 보완

5. **브랜드·모델 정규화**  
   - `Herman Miller` / `허먼밀러`, `Aeron` / `에어론` 동의어 사전  
   - 키워드 생성·Matching 프롬프트·titleSimilarity에 동일 사전 사용

6. **OCR 실사용**  
   - 고점수 후보(또는 이미지 텍스트 많은 카테고리)만 `AI_OCR_BEFORE_MATCH`  
   - listing 이미지 OCR → `scores.ocr`에 실제 반영

7. **부정 신호 강화**  
   - 제목에 “헤드레스트만”, “부품”, “삽니다” 등 → Matching 상한 또는 exclude Rule  
   - 의자 베이스만 나온 사진 등은 Vision/Local 저점과 결합

8. **프롬프트 버전 실험**  
   - “동일 상품 vs 유사 라인업(클래식 vs 뉴 에어론)” 구분 강화  
   - Prompt Version + A/B로 오탐·미탐 측정

### P1 — 이미지 Matching 보완

9. **Local 점수를 Vision 경로에도 blend**  
   - Vision 호출 전 Local max(SSIM, OpenCV, …)를 보조 점수로 남김  
   - Vision 실패 시 Local로 하향/유지 (지금처럼 텍스트만 두지 않기)

10. **실루엣 / 엣지 비교 (선택)**  
    - 부분 촬영(다리만, 등판만)에서 ORB·SSIM이 약할 때 형태 보조  
    - 가구 카테고리 한정으로 켜기

11. **크롤 단계 aHash 안정화**  
    - 렌탈 썸네일 해시 필수화 → `imageSimilarity`가 상위 N 선정에 기여

12. **Matching ↔ Compare 엔진 정렬 (중장기)**  
    - UI 비교와 자동 Matching이 같은 Local 엔진·같은 threshold를 쓰도록 통합  
    - 지금은 `AI_LOCAL_*`(Matching) vs `COMPARE_*`(UI 브랜치) 이중 구조

### P2 — 운영·품질

13. **매칭 품질 대시보드**  
    - Vision 호출률 / Local block률 / Investigation 생성률 / 수동 기각률  
    - threshold 튜닝 근거

14. **휴먼 피드백 루프**  
    - Investigation에서 “동일 / 다름” 판정 → 프롬프트·Rule·가중치 개선 데이터

15. **카테고리별 프로필**  
    - 오피스체어 vs 소파 vs 조명: 색·OCR·가격 가중치 다르게

## 5. 추천 로드맵 (요약)

| 단계 | 내용 | 기대 효과 |
|------|------|-----------|
| **지금~단기** | 점수 영속화, 렌탈 price/color 전달, 70~89 워치리스트 | 조사 근거 투명, 미연결 케이스 감소 |
| **단기** | 2패스 Matching, 동의어, OCR 선택 적용 | 동일 상품 미탐↓ |
| **중기** | Local+Vision blend, 부정 키워드 Rule, 품질 메트릭 | 오탐↓ · 비용 유지 |
| **중장기** | Matching/Compare 엔진 통합, 카테고리 프로필, 피드백 루프 | 조사 일관성 |
