# Search Crawler 사용법

가구 렌탈 상품이 중고거래 사이트(중고나라 · 번개장터 · 당근)에 재판매되었는지 탐지하는 **검색 크롤러 + 운영 대시보드** 사용 안내입니다.

---

## 1. 시작하기

### 1.1 최초 준비

```powershell
cp .env.example .env
npm install
npm --prefix web install
npx playwright install chromium
```

`.env`에서 확인할 값:

| 키 | 설명 |
|----|------|
| `API_KEY` | API · 대시보드 인증 (`x-api-key`) |
| `JWT_SECRET` | JWT용 비밀값 (운영에서는 `API_KEY`와 다르게) |
| `PORT` | API 포트 (기본 `3100`) |
| `NODE_ENV` | `development`(로컬) / `production`(운영) |
| DB / Redis / Elastic 호스트 | Windows에서는 **`127.0.0.1`** 권장 |

#### API 키 · JWT 비밀값 (로컬 vs 운영)

| 환경 | `NODE_ENV` | 예제값 (`change-me-*`) | 해야 할 일 |
|------|------------|------------------------|------------|
| 로컬 | `development` (또는 미설정) | **허용** | `.env` 예제값 그대로 OK. 대시보드 Health의 API Key만 맞추면 됨 |
| 운영 | `production` | **기동 거부** | 아래 절차대로 교체 |

운영 배포 시:

1. `API_KEY` / `JWT_SECRET`을 각각 **24자 이상**, **서로 다른** 무작위 값으로 설정합니다.
2. 백오피스·외부 연동 클라이언트의 `x-api-key`를 같은 `API_KEY`로 맞춥니다.
3. 대시보드는 우측 상단 Health에서 API Key를 운영 키로 입력합니다. (브라우저 localStorage에 저장)
4. 예제값·짧은 값으로 운영 기동을 시도하면 서버가 즉시 종료됩니다. 이는 의도된 동작입니다.

```env
# 로컬
NODE_ENV=development
API_KEY=change-me-api-key
JWT_SECRET=change-me-jwt-secret

# 운영 예시
NODE_ENV=production
API_KEY=<24자+ 무작위>
JWT_SECRET=<다른 24자+ 무작위>
```

### 1.2 실행 (`r.bat` 권장)

프로젝트 루트에서:

```bat
r              인프라 + API + Worker + Web
r all          API + Worker + Web만 (인프라가 이미 떠 있을 때)
r infra        Postgres / Redis / Elastic 기동
r down         인프라 중지
r api          API만
r worker       Worker만
r web          대시보드만
r help         도움말
```

| 항목 | URL |
|------|-----|
| Web 대시보드 (Vite 개발) | http://127.0.0.1:5173 |
| Web 대시보드 (Docker Compose) | http://127.0.0.1:8080 |
| API | http://127.0.0.1:3100 |

대시보드 우측 상단 Health 영역에서 **API Key**를 `.env`의 `API_KEY`와 동일하게 입력합니다.

### 1.3 회귀 테스트

코드 변경 후 아래를 실행해 P0/P1 핵심 동작을 확인합니다.

```powershell
npm test
npm run build
npm run web:build:check
# Docker 필요 — 빈 DB에 migration 적용 검증
npm run test:migration
```

커버 범위: 검색 이력 스냅샷 보존, Search Job 상태 전이, 어댑터 정규화, 이미지 SSRF/크기 제한, API 키·운영 secrets 가드, 빈 volume migration.

Docker 전체 스택(API+Worker+Dashboard):

```powershell
docker compose up -d --build
# Dashboard http://127.0.0.1:8080  /  API http://127.0.0.1:3100
```

인프라·API 포트는 `127.0.0.1`에만 열려 있습니다.

## 3. Dashboard — 상품 검색

### 3.1 검색 실행

1. Dashboard (`/`) 상단 **Search Toolbar**에서 키워드(상품명)를 입력합니다.
2. 필요 시 사이트(중고나라 / 번개장터 / 당근)를 선택합니다.
3. **강제크롤**은 평소에는 **끄고** 검색합니다. (필요할 때만 ON — 아래 3.2 참고)
4. 검색을 실행하면 진행률이 **Progress**에 표시됩니다.
5. 좌측 **최근 검색**, 우측 **검색 결과** 카드가 갱신됩니다.

### 3.2 일반 검색 vs 강제 크롤

**강제 크롤을 항상 켤 필요는 없습니다.** 기본은 OFF입니다.

| 모드 | 체크 | 동작 |
|------|------|------|
| **일반 검색** | 강제크롤 OFF | 해당 키워드로 **이미 크롤한 결과**가 Elastic에 있으면 즉시 표시(캐시). 없으면 자동으로 크롤 |
| **강제 크롤** | 강제크롤 ON | 캐시를 무시하고 **항상 새로 크롤**. 최신 매물을 다시 긁을 때 사용 |

#### 언제 무엇을 쓰나

| 상황 | 권장 |
|------|------|
| 일상 조회 · 같은 키워드 다시 보기 | 일반 검색 (강제크롤 OFF) |
| 한 번도 안 검색한 **새 키워드** | 일반 검색만으로도 자동 크롤 |
| 방금 올라온 매물까지 **최신화** | 강제 크롤 ON |
| 캐시가 오래됐거나 결과가 이상할 때 | 강제 크롤 ON |
| 예전에 돌린 검색을 다시 열기 | 왼쪽 **최근 검색** 히스토리 클릭 (재검색 불필요) |

#### 캐시가 키워드별로 구분되는 방식

- 캐시는 **검색 키워드 정확 일치** 기준입니다.  
  예: `아이폰 13` 캐시와 `아이폰 15` 캐시는 **서로 다른** 결과입니다.
- `아이폰 13`을 한 번도 크롤하지 않았다면 → 일반 검색해도 캐시 miss → 새로 크롤합니다.
- 같은 키워드를 다시 검색하면 → 캐시 hit → 즉시 표시합니다.

#### 활용 예시

```
1) 「시몬스 침대」 검색 (강제크롤 OFF)
   → 처음이면 크롤, 이후에는 캐시로 즉시 표시

2) 며칠 뒤 최신 매물이 궁금할 때
   → 같은 키워드 + 강제크롤 ON → 새로 긁음

3) 「아이폰 13」 / 「아이폰 15」 각각 검색
   → 키워드가 다르므로 결과가 따로 쌓임 (서로 섞이지 않음)

4) 왼쪽 히스토리에서 과거 검색 클릭
   → 그때의 검색 결과를 다시 로드 (크롤 아님)
```

### 3.3 검색 결과 활용

결과 카드에서:

| 동작 | 설명 |
|------|------|
| 카드 클릭 | 우측 **상품 상세 Drawer** (이미지 비교 · AI 분석 · 원본 URL) |
| **조사 시작** | Investigation Case 생성 (페이지 이동 없음) |

조사 시작 시:

- Case Number 예: `CASE-20260724-000001`
- Toast: `Investigation이 생성되었습니다.`
- 검색 화면을 벗어나지 않고 **Case Drawer**에서 바로 이어서 작업할 수 있습니다.

### 3.4 최근 검색 · 결과 패널

- **모든 검색 이력**은 DB에 남습니다. 결과가 “사라진” 것처럼 보여도 삭제된 것이 아닙니다.
- 우측 **결과 패널**은 **현재 선택한 검색 1건**만 표시합니다.
- 왼쪽 **최근 검색**을 클릭하면 해당 검색의 결과를 다시 불러옵니다.
- 키워드 입력란은 선택한 검색의 키워드와 맞춰집니다.

### 3.5 Summary

페이지 하단:

1. **검색 Summary** — 검색 수 · 결과 수 · 오늘 · Queue  
2. **Investigation Summary** — Open / Investigating / Review / Completed 건수  

Investigation Summary의 **목록** 링크로 Case 목록으로 이동할 수 있습니다.

## 5. Investigation — Case 관리

재판매 의심 매물을 Case로 모아 조사합니다.  
**목록은 Investigation 페이지**, **상세·작업은 항상 Drawer**에서 수행합니다.

### 5.1 목록

`/investigation`

- 검색: Case No · 상품명 · 담당자
- 필터: 상태 · 사이트
- 행 클릭 → 우측 **Case Drawer** (페이지 이동 없음)

### 5.2 Case Drawer (섹션 네비)

상단 Sticky 탭으로 바로 이동합니다.

| 탭 | 내용 |
|----|------|
| **Overview** | Case 메타 · Workflow · Assignment · 상품 정보 |
| **AI** | 이미지/상품명/브랜드/모델/가격/OCR 유사도 · AI Score · AI 판단 |
| **Timeline** | 검색 · AI · 생성 · Evidence · 담당 · 메모 · 상태 · 판정 이력 (시간순) |
| **Evidence** | 원본 URL · 스크린샷 · 상품 이미지 · OCR · HTML Snapshot (다운로드 / 삭제) |
| **Work** | Notes · Final Decision |

ESC · 배경 · X 로 Drawer를 닫습니다. 검색 중이던 페이지는 그대로입니다.

### 5.3 Workflow (상태)

```
Open → Investigating → Review → Completed → Archived
```

- Dropdown으로 **한 단계씩**만 변경
- 변경 내용은 **Timeline**에 자동 기록
- **Completed 이후**: Notes / Evidence / Assignment 수정 불가 (Archived로만 이동 가능)
- **Archived**: 상태 변경 불가

### 5.4 Assignment (담당)

| 항목 | 설명 |
|------|------|
| 담당자 | 후보 목록에서 지정 / 미지정 |
| 우선순위 | High / Medium / Low (Badge) |
| 마감일 | 날짜 선택 |

담당자 변경 시 Timeline에 **담당자 지정**이 기록됩니다.

### 5.5 Notes (메모)

- Plain text만 지원 (Markdown 없음)
- 작성 · 수정 · 삭제
- 작성자 · 작성일 표시
- 입력 후 잠시 뒤 **자동 저장**

### 5.6 Evidence

각 항목: 저장일 · **다운로드** · **삭제**(잠금 전)

| 종류 | 설명 |
|------|------|
| 원본 URL | 매물 링크 |
| 스크린샷 / 상품 이미지 | 저장된 이미지 |
| OCR | 텍스트 스냅샷 |
| HTML Snapshot | HTML 보관본 |

### 5.7 Final Decision (최종 판정)

Drawer 하단 Work 영역:

| 버튼 | 의미 |
|------|------|
| 재판매 확인 | 무단 재판매로 판정 |
| 추가 조사 | 추가 조사 필요하나 Case는 완료 처리 |
| 오탐 | 오탐 판정 |
| 제외 | 조사 대상 제외 |

확인 대화상자(Confirm) 후:

- 상태가 **Completed**로 변경
- Timeline에 Final Decision · 완료 처리 기록

## 8. 권장 업무 흐름

```
1. Dashboard에서 렌탈 상품명으로 검색 (강제크롤 OFF가 기본)
        ↓
2. 필요 시만 강제크롤 ON으로 최신화
        ↓
3. 유사도·이미지 높은 결과 확인 (결과 Drawer)
        ↓
4. 의심 매물 → 「조사 시작」 (페이지 유지)
        ↓
5. Case Drawer에서 AI · Evidence · 담당자 지정 · 메모
        ↓
6. Workflow로 Investigating / Review 진행
        ↓
7. Final Decision으로 판정 → Completed
        ↓
8. 필요 시 Archived
```

목록에서 여러 Case를 관리할 때는 **Investigation** 메뉴의 테이블을 사용하고,  
검색 도중 바로 조사할 때는 Dashboard에서 Drawer만 엽니다.

## 9. 자주 하는 질문

**Q. 항상 강제 크롤을 켜야 하나요?**  
A. 아니요. **평소에는 OFF**입니다. 같은 키워드 재조회는 캐시로 빠르게 보고, **최신 매물을 다시 긁을 때만 ON** 하세요.

**Q. 강제 크롤과 일반 검색 차이는?**  
A. 일반 = 캐시 있으면 즉시 반환 / 없으면 자동 크롤. 강제 = 캐시 무시하고 항상 크롤. 자세한 표는 **§3.2** 참고.

**Q. `아이폰 13`과 `아이폰 15`를 검색했는데 결과가 같게 나왔어요.**  
A. 예전에 캐시가 제목 유사 검색으로 섞일 수 있었습니다. 현재는 **키워드 정확 일치**로만 캐시합니다. 최신이 필요하면 각 키워드로 **강제 크롤** 한 번씩 돌리세요.

**Q. 아까 검색한 「시몬스 침대」 결과가 안 보여요.**  
A. 삭제된 게 아닙니다. 결과 패널은 **지금 선택한 검색 1건**만 보여줍니다. 왼쪽 **최근 검색**에서 해당 항목을 클릭하세요.

**Q. 조사 시작 후 Investigation 메뉴로 안 넘어가나요?**  
A. 의도된 동작입니다. 검색을 끊지 않기 위해 현재 화면에서 Drawer로 작업합니다.

**Q. Case 데이터가 서버에 저장되나요?**  
A. 현재 Investigation Case는 브라우저 **localStorage**에 저장됩니다. (API/DB 연동은 후속 과제)

**Q. Completed인데 메모를 고치고 싶습니다.**  
A. Completed / Archived는 수정이 잠깁니다. 판정 전에 Notes를 완료하세요.

**Q. API Key 오류가 납니다.**  
A. 대시보드 Health 영역의 Key와 `.env`의 `API_KEY`가 같은지 확인하세요.

**Q. Windows에서 DB/Redis 연결이 실패합니다.**  
A. `localhost` 대신 **`127.0.0.1`** 을 사용하세요.
