# Search Crawler 배포 가이드

이 문서는 **다른 Windows 로컬 PC**와 **Ubuntu 운영 서버**에서  
Git으로 코드를 받은 뒤 **설치 → 설정 → 실행**까지 가는 전체 절차를 정리합니다.

| 구분 | 권장 실행 방식 | Web | API |
|------|----------------|-----|-----|
| Windows 로컬 개발 | Docker 인프라 + `r.bat` / `npm run dev` | Vite `5173` | `3100` |
| Ubuntu 운영 | Docker 인프라 + **PM2** (`ecosystem.config.js`) | `serve` `5173` | `3100` |
| (선택) Docker 풀스택 | `docker compose up` | Dashboard `8080` | `3100` |

저장소(예시):

```text
https://github.com/LicheLDK/lomad2-crawler_mywork.git
```

관련 문서:

- 일상 사용: [`사용법.md`](./사용법.md)
- DB migration: [`database_migrations.md`](./database_migrations.md)
- 점검 이력: [`PROJECT_REVIEW.md`](./PROJECT_REVIEW.md)

---

## 0. 구성 개요

```text
[브라우저]
   │
   ├─ Web Dashboard  (개발: Vite 5173 / 운영 PM2: serve 5173 / Compose: nginx 8080)
   │
[Nest API :3100]  ←── x-api-key
   │
   ├── PostgreSQL :5432
   ├── Redis :6379          (BullMQ 큐)
   ├── Elasticsearch :9200
   └── Worker (Playwright/HTTP 크롤)
```

- API와 Worker는 **같은 코드베이스**입니다. `ENABLE_WORKER`로 역할을 나눕니다.
- 운영(`NODE_ENV=production`)에서는 TypeORM `synchronize`가 **꺼집니다**.  
  → **반드시 migration**을 실행해야 테이블이 생깁니다.
- 운영에서는 `API_KEY` / `JWT_SECRET`이 예제값(`change-me-*`)이면 **기동 자체가 거부**됩니다.

선택 항목:

| 키 | 설명 |
|----|------|
| `OPENAI_API_KEY` | AI 키워드/조사 기능 사용 시 |

| `BACKOFFICE_ORDER_URL_TEMPLATE` | Investigation 주문 링크 |

# B. Ubuntu 운영 — Git 설치부터 PM2 실행

운영은 **`NODE_ENV=production` + PM2** 를 기준으로 합니다.  
인프라(Postgres/Redis/Elastic)는 Docker Compose로 올리는 방식을 권장합니다.

## B-1. 서버 사전 준비 (한 번만)

### Step 1. OS 패키지 / 계정

```bash
sudo apt update
sudo apt install -y curl git ca-certificates build-essential
```

배포용 사용자(예: `deploy`)로 작업하는 것을 권장합니다.

### Step 2. Node.js 22 설치

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node -v   # v22.x
npm -v
```

### Step 3. Docker / Compose 설치

Ubuntu용 Docker 공식 설치 후:

```bash
sudo usermod -aG docker $USER
# 로그아웃 후 재접속
docker version
docker compose version
```

### Step 4. PM2 전역 설치

```bash
sudo npm install -g pm2
pm2 -v
```

### Step 5. (권장) 방화벽

인프라(5432/6379/9200)는 **외부에 열지 마세요**.  
Compose는 이미 `127.0.0.1` 바인딩입니다.

예: API/Web만 공개 (또는 앞단 Nginx만 공개)

```bash
sudo ufw allow OpenSSH
sudo ufw allow 3100/tcp    # API (또는 Nginx만 열고 API는 localhost)
sudo ufw allow 5173/tcp    # Web (또는 Nginx reverse proxy)
sudo ufw enable
sudo ufw status
```

실무에서는 **Nginx(443) → localhost:3100 / localhost:5173** 이 더 안전합니다.


**필수 변경 예시:**

```env
NODE_ENV=production
PORT=3100
APP_NAME=search-crawler-server

# 반드시 예제값 금지 — 각각 24자 이상, 서로 다른 값
API_KEY=여기에_충분히_긴_무작위_API_키
JWT_SECRET=여기에_다른_충분히_긴_JWT_비밀값

DB_HOST=127.0.0.1
DB_PORT=5432
DB_USER=crawler
DB_PASSWORD=강한_DB_비밀번호

REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=

# 백오피스 연동 (운영 URL)

RENTAL_API_KEY=...
RENTAL_SEARCH_CALLBACK_ENABLED=true

BACKOFFICE_ORDER_URL_TEMPLATE=https://backoffice.example.com/getOrderInfo?order_id={orderNo}

# AI (사용 시)
OPENAI_API_KEY=...
```

비밀값 생성 예:

```bash
openssl rand -base64 48
```

Compose의 Postgres도 같은 `DB_USER` / `DB_PASSWORD` / `DB_NAME`을 쓰도록 `.env`와 맞춥니다.

> `ecosystem.config.js`의 API/Worker는 `NODE_ENV=production`으로 기동됩니다.  
> 예제 `change-me-*` 키면 **즉시 종료**됩니다.

### Step 8. Web 빌드용 `web/.env`

Vite 환경변수는 **빌드 시점**에 박힙니다. PM2 `serve`로 정적 파일을 올릴 때도 미리 맞춰야 합니다.

```bash
cat > web/.env <<'EOF'
VITE_API_BASE=http://127.0.0.1:3100/api
VITE_BACKOFFICE_ORDER_URL_TEMPLATE=https://backoffice.example.com/getOrderInfo?order_id={orderNo}
EOF
```

브라우저가 **다른 도메인/공인 IP**로 API에 접근한다면:

```env
VITE_API_BASE=https://crawler.example.com/api
VITE_SOCKET_URL=https://crawler.example.com
```

그리고 Nest CORS(`src/main.ts`)에 해당 Web Origin을 추가한 뒤 다시 빌드해야 합니다.  
(로컬호스트만 쓸 때는 기본 CORS로 충분합니다.)

## B-4. PM2로 실행

`ecosystem.config.js`가 다음 3 프로세스를 띄웁니다.

| PM2 이름 | 역할 | 비고 |
|----------|------|------|
| `crawler-api` | Nest API | cluster × 2, `ENABLE_WORKER=false`, port 3100 |
| `crawler-worker` | 크롤 워커 | fork × 1, `ENABLE_WORKER=true` |
| `crawler-web` | 정적 대시보드 | `serve` → `127.0.0.1:5173` |

### Step 13. 기동

```bash
npm run pm2:start
# 동일: pm2 start ecosystem.config.js
pm2 status
pm2 logs
```

### Step 14. 부팅 시 자동 기동

```bash
pm2 save
pm2 startup
# 출력되는 sudo 명령을 복사해 실행
pm2 save
```

### Step 15. 접속 확인

서버에서:

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3100/api/health
# health 경로가 다르면 docs 또는 System 화면으로 확인

```

브라우저:

| 항목 | URL (서버 IP/도메인에 맞게) |
|------|------------------------------|
| Web | http://`<서버>`:5173 |

백오피스/연동 시스템에도 **동일한 `x-api-key`** 를 설정합니다.

### 파일 로그 (개발·운영 공통)

앱이 터미널·파일 모두 **들여쓴 JSON** 으로 남깁니다. (`LOG_PRETTY=false` 또는 `LOG_COMPACT=true` 이면 터미널만 한 줄 NDJSON)

| 경로 | 내용 |
|------|------|
| `logs/api/current.log` | API 구조화 로그 (request completed 등) — 최신 symlink |
| `logs/api/api.YYYY-MM-DD.N.log` | pino-roll 일/크기 로테이션 보관본 |
| `logs/worker/current.log` | Worker 구조화 로그 |
| `logs/web/web.log` | Vite(개발) 콘솔 파일 로그 |
| `logs/*/pm2-*.log` | PM2 stdout/stderr 캡처 (운영) |

환경 변수 (선택):

| 변수 | 기본 | 설명 |
|------|------|------|
| `LOG_APP` | api / worker 자동 | `api` \| `worker` \| `web` |
| `LOG_FILE` | `true` | 파일 로그 on/off |
| `LOG_LEVEL` | dev=`debug`, prod=`info` | |
| `LOG_PRETTY` | `true` | `false`면 터미널 한 줄 NDJSON |
| `LOG_COMPACT` | `false` | `true`면 터미널 한 줄 NDJSON |
| `LOG_FREQUENCY` | `daily` | pino-roll 주기 |
| `LOG_SIZE` | `20m` | 파일 최대 크기 |
| `LOG_RETENTION` | `14` | 보관 개수 (활성 제외) |
| `LOG_DIR` | `./logs` | 루트 디렉터리 |
| `TYPEORM_LOGGING` | 개발 on / 운영 off | SQL 쿼리 로그 (pino 경유 → 파일 포함) |
| `TYPEORM_SLOW_MS` | `1000` | 이 시간(ms) 초과 시 slow query warn |

Ubuntu logrotate (운영 권장):

```bash
sudo cp deploy/logrotate/lomad-crawler /etc/logrotate.d/lomad-crawler
# 파일 안 경로를 실제 배포 경로에 맞게 수정
sudo logrotate -d /etc/logrotate.d/lomad-crawler
```

개발(`npm run dev`)에서도 PM2 없이 `logs/api`, `logs/web` 파일이 생성됩니다.

## B-6. (선택) Nginx 리버스 프록시

공인 HTTPS를 쓸 때 예시:

```nginx
server {
  listen 443 ssl http2;
  server_name crawler.example.com;

  # ssl_certificate ...;

  location /api/ {
    proxy_pass http://127.0.0.1:3100/api/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  location /socket.io/ {
    proxy_pass http://127.0.0.1:3100/socket.io/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
  }

  location / {
    proxy_pass http://127.0.0.1:5173/;
    proxy_set_header Host $host;
  }
}
```

이 경우 `web/.env`의 `VITE_API_BASE` / `VITE_SOCKET_URL`을 해당 도메인으로 맞추고 **재빌드**합니다.

# D. 자주 나는 문제

| 증상 | 원인 / 조치 |
|------|-------------|
| 운영 기동 직후 종료, secrets 오류 | `API_KEY`/`JWT_SECRET`이 예제·짧음 → 24자+ 서로 다른 값으로 교체 |
| 테이블 없음 / relation 오류 | production에서 migration 미실행 → `npm run migration:run:prod` |
| Redis 연결 실패 | `npm run infra:up`, `REDIS_HOST=127.0.0.1` |
| Elastic 연결 실패 | 컨테이너 healthy 대기, `ELASTIC_NODE=http://127.0.0.1:9200` |
| 대시보드 401 | Health의 API Key ≠ `.env` API_KEY |
| Web은 뜨는데 API 호출 실패 | `web/.env`의 `VITE_API_BASE`가 빌드에 반영됐는지(재빌드), CORS Origin |
| Playwright 크롤 실패 | `npx playwright install --with-deps chromium` |
| Windows `localhost` 이슈 | DB/Redis/Elastic을 `127.0.0.1`로 통일 |
| PM2 web만 404 | `npm run web:build` 후 `web/dist` 존재 여부 확인 |

# E. 빠른 명령 요약

### Windows 로컬

```powershell
git clone <repo-url> && cd lomad2-crawler_mywork
Copy-Item .env.example .env
npm install
npm --prefix web install
npx playwright install chromium
npm run infra:up
r
```

### Ubuntu 운영 (PM2)

```bash
git clone <repo-url> && cd lomad2-crawler_mywork
cp .env.example .env   # 실 비밀값으로 편집
# web/.env 작성
npm install && npm --prefix web install
npx playwright install --with-deps chromium
npm run infra:up
npm run build:all
npm run migration:run:prod
mkdir -p storage/images logs
npm run pm2:start
pm2 save && pm2 startup
```
